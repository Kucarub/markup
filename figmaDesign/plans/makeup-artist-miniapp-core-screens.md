# 妆集化妆师端 5 个核心界面实施计划

## 1. 目标与交付范围

在当前空白的 React 19 + Vite 8 + Tailwind CSS v4 项目中，实现一套可在浏览器预览、可点击操作的化妆师端小程序高保真原型。视觉和内容严格参考附件《妆集 · 化妆师作品集与接单门户 — Figma 界面设计规范》，聚焦以下 5 个核心界面：

1. `MP-Home-工作台`
2. `MP-Demand-需求大厅`
3. `MP-Demand-需求详情`
4. `MP-Portfolio-作品集列表`
5. `MP-Mine-个人中心`

交付重点是展示小程序核心产品语言、作品摄影、信息层级和主要交互，不接后端，不实现真实登录、上传、支付或即时聊天。

## 2. 产品流程与导航

- 应用以 375px 小程序内容宽度为设计基准，在窄屏设备上铺满视口；桌面预览时置于居中的手机画布中，并使用低干扰的暖灰页面背景衬托。
- 底部固定 4 项 TabBar：`工作台 / 需求大厅 / 作品集 / 我的`。
- TabBar 仅出现在 4 个一级页面；需求详情进入后隐藏 TabBar，改为顶部返回导航和底部固定投递操作栏。
- 工作台的“适合你的需求 / 全部”与推荐需求卡可进入需求大厅或对应需求详情。
- 需求大厅支持搜索、筛选胶囊的选中态，以及点击需求卡进入详情。
- 需求详情支持收藏切换、要求文字展开/收起、首次投递确认；投递后按钮改为“已投递，查看进度”，并显示短暂 Toast。
- 作品集页支持分类分段切换；“新建作品集”展示轻提示，说明完整编辑流程不在本轮 5 页范围内。
- 个人中心的功能项保留可点击反馈；“档期管理”等未纳入本轮的页面通过 Toast 表达后续入口，避免无响应控件。

## 3. 视觉系统

### 3.1 设计令牌

在 `src/index.css` 中建立 CSS 自定义属性，并映射附件中的核心令牌：

- 品牌色：`#B4566E / #C96D84 / #F7E7EC / #FCF5F7`
- 中性色：`#1A1A1A / #4A4A4A / #8C8C8C / #BFBFBF / #E8E8E8 / #F5F5F5 / #FFFFFF`
- 功能色：成功 `#2FA36B`、警告 `#E39A2B`、错误 `#D9483B`、信息 `#3B7FD9`
- 字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", sans-serif`
- 4pt 间距体系、4/8/12/16/full 圆角及轻量阴影。

全局样式放入 `@layer base`，确保 Tailwind 工具类仍可覆盖；补充安全区、隐藏滚动条、图片裁切和按钮按压等少量通用工具样式。

### 3.2 视觉基调

- 保持“干净、专业、有质感、不打扰作品”：白色主背景、豆沙玫瑰作唯一主强调色、充足留白、细边框和极轻阴影。
- 卡片圆角不超过 12px，弹层不超过 16px；避免大面积渐变和装饰性背景。
- 使用线性、2px 圆角端点风格图标；通过 `lucide-react` 提供统一图标集，不使用 emoji。
- 内容区左右 16px；模块间距 24px；卡片间距 12px；固定导航和操作区考虑 `env(safe-area-inset-*)`。
- 动效保持 100–300ms：按钮按压缩放、筛选切换、页面进入、Toast 淡入淡出；不使用弹跳动效。

### 3.3 摄影素材

- 从已检索的 Unsplash 美妆与新娘肖像结果中选取一组风格一致的高清竖幅作品照，分别用于头像、工作台需求氛围图和作品集封面。
- 统一采用 1:1、3:4 或 16:9 的 `object-cover` 中心裁切，控制 URL 请求宽度以兼顾清晰度和加载性能。
- 所有图片提供描述性中文 `alt`；头像等纯装饰性缩略图使用恰当的空 `alt`，避免重复朗读。

## 4. 页面规格

### 4.1 工作台

- 顶部模拟小程序安全区和自定义导航：上海城市入口、品牌字标、带未读红点的消息铃铛。
- 个人状态卡：头像、L2 等级角标、姓名、作品/投递数据、82% 资料完整度及“完善资料”按钮。
- 四等分数据条：作品浏览、被查看、待回复、本月邀约。
- 近期档期：7 天横向日期胶囊，区分今日、可约、已约。
- 推荐需求：3 张 `DemandCard`，突出报酬、标题、场合/人数/时长、日期、地点和截止状态。
- 保持内容可纵向滚动，底部留出 TabBar 安全距离。

### 4.2 需求大厅

- 顶部标题与搜索框，占位文案逐字使用“搜索需求/场合/商家”。
- 横向滚动筛选胶囊：全部场合、报酬、日期、距离、仅看可约；点击后显示明确选中态。
- 展示 5–6 条具有不同状态的需求卡：招募中、即将截止、已招满。
- 搜索和“仅看可约”对本地列表产生真实过滤效果；无结果时展示规范空态“当前城市暂无匹配需求 / 换个筛选条件，或开启新需求提醒 / 放宽筛选条件”，按钮可清除筛选。

### 4.3 需求详情

- 自定义导航栏：返回、居中标题、分享操作。
- 顶部信息卡：需求标题、已认证商家、报酬与时长。
- 需求要素双列信息表：场合、日期、时段、地点、人数、妆容类型、化妆箱和结算方式。
- 商家要求支持 6 行截断和展开。
- 技能匹配卡突出“与你的匹配度 85%”，显示匹配与不匹配标签。
- 底部固定操作栏：收藏按钮与投递按钮；已招满数据时自动禁用投递。
- 投递成功后更新本地 UI 状态并显示 Toast，不伪造后台请求。

### 4.4 作品集列表

- 顶部标题和“+ 新建作品集”主按钮。
- 分类分段控件：全部、新娘妆、生活妆、舞台妆、证件照。
- 2 列视觉瀑布流；作品卡封面采用 3:4 与 1:1 混排，展示作品名、风格标签、作品数量和发布状态。
- 分类切换真实过滤本地作品数据；包含已发布、草稿、审核中三种状态。
- 当分类无内容时使用规范空态“还没有作品集 / 上传第一组作品，让商家看到你 / 创建作品集”。

### 4.5 个人中心

- 顶部品牌浅色状态区：头像、姓名、等级徽章、82% 资料完整度进度条。
- 一组关键数据快捷统计：作品、收藏、投递。
- 功能列表按规范呈现：我的投递、我的收藏、档期管理、技能认证、我的等级、帮助与反馈、关于我们；“我的投递”带数量角标。
- 底部提供低强调度“退出登录”按钮；点击后展示确认式反馈或 Toast，不改变全局登录态。

## 5. 组件与数据结构

### 5.1 组件拆分

在 `src/App.tsx` 内保持页面编排和顶层状态，在 `src/components/` 下拆分可复用 UI：

- `MobileShell`：375px 画布、滚动区、安全区。
- `TopNav`、`TabBar`：一级与详情页导航。
- `IconButton`、`Button`、`Tag`、`LevelBadge`、`Avatar`：基础组件。
- `DemandCard`：工作台与需求大厅共用，通过 compact/完整模式复用。
- `PortfolioCard`：作品封面、标签、状态。
- `AvailabilityStrip`：近期档期日期条。
- `EmptyState`、`Toast`：通用反馈。

组件采用明确的 TypeScript props 和语义化按钮元素；状态色和尺寸统一走 CSS 令牌与 Tailwind 类。

### 5.2 本地演示数据

- 在 `src/data/mockData.ts` 定义 `Demand`、`Portfolio`、用户概览和档期数据。
- 至少包含 6 条需求与 6 个作品集，覆盖筛选、空态、招满、临近截止、审核中和草稿状态。
- 所有时间、金额和地点使用统一中文格式，数字字段使用 tabular numerals。
- 页面选择、筛选、收藏和投递均为 React 本地状态；刷新页面后允许重置。

## 6. 文件变更

- `package.json`：增加 `lucide-react` 图标依赖。
- `src/App.tsx`：应用入口、页面路由状态和核心交互。
- `src/index.css`：设计令牌、基础样式、移动画布与轻量动效。
- `src/components/*`：可复用基础与业务组件。
- `src/pages/*`：5 个页面组件，其中需求详情作为二级页面。
- `src/data/mockData.ts`：演示数据与 TypeScript 类型。

不增加后端、路由库、状态管理库或环境变量；页面数量有限，使用轻量的本地页面状态即可。

## 7. 响应式与可访问性

- 320–430px 宽度保持内容自适应；375px 为基准，不产生横向页面滚动，只有明确的筛选/日期横向列表可横向滚动。
- 桌面仅增加外围展示背景与手机画布阴影，不把小程序页面拉伸成桌面布局。
- 所有可点击目标至少 40×40px，主按钮 48px 高。
- 交互控件提供 `aria-label`、可见焦点态和正确的 `disabled` 状态；导航项使用按钮语义。
- 文本对比度、状态表达不只依赖颜色，状态标签同时保留文字。
- 尊重 `prefers-reduced-motion`，减少页面位移与过渡。

## 8. 验收与验证

### 8.1 功能验收

- 4 个底部 Tab 均可切换且选中态正确。
- 工作台和需求大厅均可进入需求详情，返回时回到来源页。
- 搜索、仅看可约、作品分类筛选能更新列表，并能触发和恢复空态。
- 收藏、展开要求、投递操作有即时且一致的 UI 反馈。
- 所有可见按钮都有响应，不保留死控件或占位按钮。
- 需求详情固定操作栏与一级页 TabBar 不互相遮挡。

### 8.2 视觉验收

- 核对 375px 与 320px 窄屏截图：层级、间距、裁切、固定栏和安全区。
- 核对 1440px 桌面预览：手机画布居中且不被拉伸。
- 检查品牌色、字号、圆角、边框、图标风格和卡片密度符合附件规范。
- 确认图片加载失败时仍有合理背景，不造成布局坍塌。

### 8.3 工程验证

- 按仓库脚本执行 `pnpm build`，修复所有 TypeScript/Vite 构建错误。
- 执行 `pnpm format` 后再次确认构建。
- 不启动额外开发服务器；使用 Figma Make 已运行的 Vite 预览和热更新进行最终人工检查。

## 9. 明确不在本轮范围

- 角色选择/登录、作品集编辑上传、分享卡片、档期月历、消息中心、我的投递详情。
- 真实微信小程序 API、后端接口、账号状态持久化、图片上传、推送与定位。
- B 端 Web、运营后台、支付、会员、在线聊天、评价体系和深色模式。
